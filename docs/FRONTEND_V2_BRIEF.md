## Rules

1. **Only create/edit files you own** (listed in your task). If you need a change in a shared file, put a short note in your final report instead — except you may *append* new keys to `Errors` in `messages/en/common.json` if strictly needed (add, never rename).
2. All UI text in messages (lint rule `react/jsx-no-literals` forbids JSX string literals; punctuation like `·` `→` `(` `)` is allowed). No product name literal (`APP_NAME` / `useAppName()`).
3. TypeScript strict, no `any`. Next.js 16 App Router: page `params`/`searchParams` are Promises (`PageProps<'/s/[slug]'>` global type exists). Pages that read `useSearchParams` in client components must be wrapped in `<Suspense>`.
4. Mutations = async functions in `src/lib/api/<domain>.ts`: validate with Zod, `await latency()`, `transact(...)`, return `Result<T>`, guard with `guard(db, persona)`. Reads = pure selectors `(db: DemoDB, …) => …`. These signatures become the backend contract, so name them after ARCHITECTURE §5.2 actions and document each with a one-line comment.
5. Every flow must be *really* interactive: buttons change state, state persists (store), empty/loading/error states exist, pending states show (`loading` prop), destructive actions confirm. No dead buttons, no `href="#"`.
6.
