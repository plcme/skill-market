## 1. 一句话定位

把澳洲劳动力市场需求渲染成**股票盘面**，让学生持有并追踪自己的技能仓位；再由**盘面异动**触发，把学生匹配给**持有该技能的在职者**做 20 分钟的咖啡聊。

两个功能是一件事，不是两件事——**匹配理由来自市场信号**（C7）。这是全竞品图里唯一没有人填的格子，也是"我们不是把两个功能硬拼"的核心论据（brief 明确说明组合功能不加分）。

## 2. Task 2 — PACT 分析

### 2a. 利益相关者与用户

**主要用户（Primary）**
- 大学在读学生
  - 大一/大二：专业未定或在摇摆，需要**广度探索**
  - 大三/大四：方向已定，需要**深度决策**（选修、实习、graduate program）
  - **国际学生**：额外受签证/工作权利约束，被现有中介体系系统性亏待（见 §2.4）
- 在职从业者（供给侧）
  - 近 3 年入行者（最贴近学生处境，最有参考价值）
  - 资深从业者（视野更广，但时间更贵）
  - 愿意/不愿意做咖啡聊的两类，招募策略完全不同

**次要用户（Secondary）**
- 高中生（选学位阶段）
- 应届/往届毕业生（求职中、或正在转行）
- 已入行但想跳行业的人

**其他利益相关者（Tertiary / Facilitating）**
- 学生家长（在子女做选择时提供建议，但信息严重滞后）
- 大学就业中心（潜在的分发渠道 + 校友供给来源 + 尽职关怀框架提供方）
- 雇主 / HR（潜在的数据与人脉来源，**但绝不能成为付费方**——见 §5.1 中介激励错配的教训）
- 政府就业部门（JSA 等，开放数据提供方）
- 求职中介与猎头（现有替代方案，也是竞争者）

> **利益立场声明**：产品**不向雇主侧收费**，否则会继承招聘中介"优化掉无经验候选人"的结构性错配。这一条应写进报告。

### 2b. 解决方案必须支持的任务

**框架决定**：主任务必须**横跨两个 feature**，否则就坐实了"两个产品硬拼"的批评。

| # | 任务 | 优先级 | 隐喻 |
|---|---|---|---|
| T1 | 查看某个技能/岗位的需求走势，可切换标的类型与 Y 轴 | 核心 | 读盘 |
| T2 | 建立并维护"我持有的技能 / 我关注的技能" | 核心 | 建仓 |
| T3 | 诊断我与目标岗位之间的技能缺口 | 核心 | 估值 |
| T4 | 由信号触发，找到并约到一个持有该技能的从业者聊 20 分钟 | 核心 | 调研 |
| T5 | 把聊天产出记回对应技能下 | should-have | 复盘 |
| T6 | 把两个选项（两门选修 / 两个方向）并排对比 | 支撑 | 比价 |
| T7 | 从业者设置可约时段、接受/改期/拒绝 | 核心（双边必需） | 挂单 |
| T8 | 设置 watchlist 提醒 / 定期 digest | 支撑 | 盯盘提醒 |

#### 主任务 T4 的步骤分解

**Happy path**
1. 学生在 watchlist 看到异动：**"Rust，过去 12 个月 +38%"**
2. 打开 ticker card 完整页 → 同现技能、entry-level 岗位占比、地区分布、薪资分位
3. 触发「找一个持有这个仓位的人聊聊」
4. 系统按**市场信号**匹配：持有该技能 + 近 3 年入行 + 已开放 availability（**不是**按专业/兴趣静态属性）
5. 返回 3 个候选人 + 由该信号自动生成的 3 条 conversation starter
6. 学生选人 → 选从业者已发布的时段 → 附带 context（年级、专业、正在纠结的具体决定）发出请求
7. 从业者接受 / 改期 / 拒绝
8. 会前提醒 + 结构化提问模板
9. 会后学生做 L0 态度投票（见 §3.5），自动打标到该技能
10. 结果回写到该 ticker 下，形成个人 research note；缺席记入 reliability 记录

**必须设计的失败分支**（只写 happy path 会显得浅）
- **匹配为空**（冷启动，§4.2(2)）→ 降级策略：放宽到相邻技能 / 排队等待 / 转推荐异步问答
- **被拒绝** → 不能让学生感到被评判，要立刻给替代候选人
- **对方不回**（最常见）→ 超时自动释放，静默换人，不让学生一直悬着
- **No-show**（ADPList 的已知问题，§5.1）→ reliability 记录 + 明确的行为规则，**上线即有，不是出问题后补**

### 2c. 用户何时执行这些任务 → 对界面的影响

时机不是均匀分布的，这一节是推导设计决策最有力的地方。

| 时机 | 特征 | 界面含义 |
|---|---|---|
| 选课 / 转专业窗口 | 有 deadline、高强度、A-vs-B | 需要**对比视图**，不是单个 card |
| Graduate program 与实习申请季（AU 大致 3–5 月 / 7–9 月） | 高焦虑、时间压力 | 需要「**现在开始学还来不来得及**」的 timing 视角 |
| 迷茫时刻（深夜、被拒之后、同学拿 offer 之后） | 低意图、碎片化、情绪化 | mobile-first、**零门槛（不登录也能看）**、绝不能有预约摩擦 |
| 例行轻检查（周/月） | 主动性低 | 靠 push / digest 触达（借 Aphinity 的 cadence，但 **need-driven** 而非纯定时） |
| 大一 vs 大三 vs 已毕业 | 深度与频率差异极大 | 同一界面须同时支持**广度探索**与**窄决策** |

**推出的三条硬约束**
1. **双模式**：30 秒 glance（digest / 通知 / 小组件）与 15 分钟 deep（对比、筛选、下钻）
2. **全流程异步**：咖啡聊是延迟满足，UI 必须优雅处理「pending 状态」——这与即时聊天的心智完全不同
3. **季节性**：申请季前后的默认视图应当不同

### 2d. 需要什么信息、如何从用户获取

**四路来源**

| 来源 | 内容 |
|---|---|
| 显式输入 | 专业 / 年级 / 预计毕业时间、已有技能、目标行业或岗位、工作权利与签证状态（敏感）、当前正在纠结的具体决定 |
| 隐式行为 | watchlist 增删、点开了什么、发起了哪些 chat、给 takeaway 打了什么标签 |
| 外部数据 | JSA NERO（月度，355 职业 × 88 区域，CC BY 4.0）、Skills Priority List、SEEK / Indeed 指数、ANZSCO 分类（详见 §5.2） |
| 供给侧 | 从业者技能、入行年份、行业、availability、愿谈话题、身份验证 |

#### Onboarding：阶梯式录入（任何一层都能停）

**绝不在入口处强制高粒度填写。**

| Tier | 耗时 | 做什么 |
|---|---|---|
| **0** | 10 秒 | 大学 + 学位 + 年级 → 系统**推断**技能画像 → **立刻看到盘面** |
| 1 | 60 秒 | 从预填列表勾选「我修过哪些课」（勾 unit code 比自写技能更省力也更准确） |
| 2 | 可选、随时 | 导入简历 / 粘贴文本 → 补上项目与实习带来的技能 |
| 3 | 持续 | 渐进式补全：「你应该用过 SQL 吧？」——用多次单点确认代替入口处的问卷墙 |

**四条加固原则**
1. **先给价值再要信息**：不登录也能看到真实盘面。直接对应「84% 知道就业中心、仅 39% 用过」的教训——官方且有用，并不解决触达。
2. **推断结果必须显式标为"猜的"且可改**，带置信度。否则要么学生不去纠正（个性化悄悄全错），要么猜得离谱（伤人）。
3. ⚠️ **伦理风险**：在"市场/持仓"框架下告诉学生「你的仓位很弱」是会打击人的，隐喻会放大伤害（你的组合在"跌"）。**这是一条明确的设计约束**，且必须进 interview 探测（做一个技能很少的新生画像 mock，看反应）。同时是 RQ2 的延伸与报告 limitation 的重要材料。
4. **简历解析必须人工复核，绝不静默生效**；简历含姓名、地址、电话、有时含签证状态 → 明确剥离并告知（连到 U7）。

### 2e. 用户期望看到什么

**学生侧**
- ticker card（定义见 §3.4）：当前值、变动、走势、**entry-level/senior 岗位占比**、薪资分位、同现技能、地区分布
- 我的持仓：持有 vs 关注，以及自建仓以来的变动
- 缺口：距目标岗位差哪几项 + 获取途径（课程 / 项目 / 证书）
- 人：谁持有这个技能、多久前入行、走的什么路径、可约时段、可靠度

**从业者侧**
- 谁在约我、**为什么约我**（信号 context）、要花多久、能否一键婉拒

> ⚠️ **自我警告**：数字越多越容易触发"指标崇拜"，让学生把隐喻当真理。直接连到 RQ2，也呼应 §7 中"股票隐喻可能误导"的自陈限制。

### 2f. 信息是否足够 → **不够**

诚实的答案是不够，且必须点明：**2a–2e 中绝大部分是团队假设，不是证据。**

| # | 未知 | 若判断错了会怎样 |
|---|---|---|
| U1 | 学生真的以 **skill** 为决策单位吗？还是 job title / 公司 / 专业？ | **粒度错 = 整个 ticker 隐喻错**，最致命 |
| U2 | 金融隐喻能被理解吗？是否只对有投资背景者有效？ | equity 问题：可能系统性排除一部分学生 |
| U3 | 学生现在实际用什么、信任什么（RQ1） | 决定我们替代谁 |
| U4 | 触发时机的真实分布（2c 全是推测） | 决定 glance 还是 deep 做默认 |
| U5 | 学生为咖啡聊愿付的代价（准备、被拒、社交焦虑） | 决定摩擦预算 |
| U6 | 从业者愿意的条件（供给侧零数据） | 冷启动可行性 |
| U7 | 用个人信息换个性化的意愿 | 2d 的输入设计 |
| U8 | 两个功能被感知为一个 workflow 吗（RQ6） | 直接检验产品论点 |
| U9 | 本地就业中心使用率是否符合美国数据（RQ7） | problem statement 的证据基础 |

**验证策略 = 三角互证**
- **Questionnaire** → 分布与优先级（广度）
- **Semi-structured interview** → 机制与原因（深度）
- **二手数据 / 竞品事实** → 第三边

## 3. 核心设计规格

### 3.1 标的类型（可切换）

| 标的类型 | 例子 | 隐喻对应 | 第一期 |
|---|---|---|---|
| **技能** | Rust, React, SQL | 个股 | ✅ |
| **岗位 / 职业** | 产品经理、数据工程师 | **ETF / 指数**（= 一篮子加权技能） | ✅ |
| 行业 | 金融科技、医疗 | 板块 | 架构预留 |
| 雇主 | Atlassian、Canva | 单一发行方 | 架构预留 |
| 证书 / 学位 | AWS 认证、Master of IT | — | 架构预留 |

**自带的导航逻辑**（Task 5a 要求写 "relationships between functions"，这段可直接用）：
- 岗位（ETF）点进去 → 成分技能及权重
- 技能（个股）点出来 → 哪些岗位持有它
- 本质上是 ITJobsWatch「co-occurring skills」面板的推广版

### 3.2 Y 轴（可切换）

**规模类（"这个盘有多大"）**
1. 绝对岗位数 — 市值
2. 占全部招聘广告比例 % — 市场份额（ITJobsWatch 核心指标）
3. ⭐ **entry-level 岗位数 / 占比** — 一个技能可以整体暴涨但对毕业生完全关闭。**全竞品无人覆盖**
4. 增长率（12 个月 %）— 收益率

**价格类**

5. 薪资中位数
6. 薪资 10–90 分位区间宽度 — **波动 / 风险带**
7. **技能溢价**（加上该技能，同类岗位薪资上浮多少）— 技能唯一正确的"价格"
8. 起薪（仅 entry-level）

**风险 / 生活质量类（无任何 LMI 工具在做，我们的空白地带）**

9. remote / hybrid 占比
10. 广告工时、全职 / 兼职 / casual 占比
11. **合同制 vs 长期雇佣占比** — 工作稳定性代理，对毕业生与签证持有者极重要
12. ⭐ **不要求 PR / 公民身份的岗位占比** — 国际学生头等大事，全市场无人做。可从广告文本抽取（如 "must have full working rights"）
13. 岗位平均挂出时长 — 雇主招不到人的程度 = 候选人议价权
14. 单个岗位平均要求几项技能 — **入行门槛**
15. **波动率**（需求序列方差）— 隐喻原生指标：技能可以在涨但极不稳定
16. ⭐ **集中度风险**（多少家不同雇主 / 行业在招）— Rust 只有 4 家在招 vs SQL 有 3000 家。**这就是分散化**，学生从没被告知过。隐喻里最有说服力的概念
17. 季节性（一年中放岗高峰）— 直接服务 2c 的"申请季"时机需求
18. 地域集中度
19. AI / 自动化暴露度 — 有价值但争议大，标为高风险项

> ⭐ = D4 确定的必进项。

**设计约束**：不要把 19 条全塞进切换器。**每种标的一个默认 Y 轴 + 4–6 个常用 + 一个"进阶"抽屉**。理由是 RQ2——指标过多直接触发指标崇拜与误读，而这是我们自陈的最大风险。

### 3.3 筛选器：复合地理条件

**需求形式**：按工作模式**分别**指定地理范围，最后取并集。

```
规则 1： 现场 / 混合   ∈ { Sydney, Melbourne }
规则 2： 远程          ∈ { Australia, New Zealand }
结果    = 规则1 ∪ 规则2
```

**由此推出的设计结论**

1. **不能用「地点下拉 + 工作模式下拉」的常规做法**——两个独立下拉在结构上表达不了这个条件。必须是**规则式 / chip 式**筛选器：一条规则 = 一种工作模式 + 一组地点，可「再加一条规则」。这是有明确 rationale 的设计决定，Task 5d 的 cognitive walkthrough 会很好写。
2. **默认极简，复合能力靠渐进披露**。默认只给一条规则。可参考先例：邮件规则、Airtable filter group、多程机票搜索——但这些都被证明对普通用户偏难。
3. **必须有自然语言回读**：「当前显示：Sydney 或 Melbourne 的现场岗位，加上澳新范围内的远程岗位」。筛选器最经典的失败就是用户不知道自己筛出了什么。
4. **地点层级**：区 → 城市 → 州 → 国家 → 区域(ANZ)，任意层级可选。JSA NERO 本身即 88 个 region 粒度，层级现成。
5. ⭐ **筛选条件是 watchlist 的一部分，不是视图设置。**「Rust，entry-level，Sydney 现场或 AU 远程」才是真正持有的那支标的。否则追踪的是全球 Rust，与用户无关。**这一点必须写进数据模型。**
6. **"样本不足"状态**：筛得太窄 → n 太小 → 曲线全是噪声。须明示「该条件下仅 7 个岗位，趋势不可靠」并建议放宽。
7. **工作权利筛选（Y 轴 #12）对国际学生的重要性不亚于地理筛选**，放在同一层。
8. **国际市场按 D3 处理**：AU/NZ 深、国际浅，且明确标注数据源不同、可比性有限。

### 3.4 什么是 ticker card

股票 app 里，ticker 是代号（AAPL），ticker card 是那个小面板：名称、当前值、涨跌、迷你走势图。

在本产品中，**ticker card = 一支标的（技能或岗位）的最小信息单元**，有三种尺寸：

| 尺寸 | 出现位置 | 内容 |
|---|---|---|
| **列表行** | watchlist | 名称 + 当前 Y 轴值 + 变动 + sparkline |
| **卡片** | 搜索结果、对比视图 | 加 entry-level 占比、地区、若干关键基本面 |
| **完整页** | 下钻 | 完整走势图 + Y 轴切换 + 同现技能 + 薪资分位 + 「找人聊」入口 |

**字段来源**（§5.2 已论证）
- **指标 schema 照搬 ITJobsWatch**：% of ads、薪资分位、排名 + 同比排名变动、三年趋势、地区分布、同现技能。数据换成澳洲的。
- **基本面面板字段照搬 LinkedIn Jobs on the Rise**：top skills、median years experience、remote share、top industries。**只取字段表，不取数据**（LinkedIn 数据不可用，见 §2.1 的硬约束）。

ticker card 是整个界面的原子单位：watchlist、搜索、对比、匹配理由，全部由它组合而成。

### 3.5 T5 复盘的分层设计

**核心原则：L0 不是"写笔记"，是"投票"。** 要求学生输出文字就死了，要求他表态就活。而且 L0 天然长在股票隐喻里，不是外挂功能。

| 层级 | 优先级 | 学生要做什么 | 我们得到什么 |
|---|---|---|---|
| **L0** | **must** | 聊完弹一次：「这次聊完，你对 Rust 的看法变了吗？」→ **更想学 / 更不想学 / 没变** + 一行可选备注。**一次点击** | ① 该 ticker 下多一条个人记录；② 聚合出**「和从业者聊过 Rust 的 14 个学生里，11 个更想学了」**——市场数据之外的**情绪面**，对应股票里的分析师观点，**无任何竞品拥有此数据** |
| L1 | should | 会前生成的 3 条 conversation starter，会后原样变成 3 个填空：「你本来打算问 X，问到了什么？」每条一行，可跳过 | 结构化 takeaway，可打标到技能 |
| L2 | should | **从业者侧**也点一次「聊了 / 没聊成」 | 出勤核实 → reliability 分数，解决 ADPList 的 no-show 问题；对从业者仅一次点击 |
| L3 | nice | 双方同意后，摘要成为该 ticker 下半公开内容 | 后来的学生能读到——真正的复利 |

> T5 是全项目**"会不会没人用"风险最高**的功能，须写进 limitation。
> Interview guide 中「聊完之后你做了什么？有记下来吗？」即用于验证 L0/L1 该做到哪一层。

## 4. Task 3 — 用户调研

### 4.1 方法选择与执行顺序

选定两种技法：**Online questionnaire**（广度）+ **Semi-structured interview**（深度）。

**关键：两者不是并列，而是有因果链的。**

```
Pilot interview（Task 3c 要求的 1 人试跑）
        ↓ 用其回答生成 questionnaire 的选项
Online questionnaire（N ≈ 40–60）
        ↓ 结尾留邮箱招募
正式 interview（学生 5–6 + 从业者 2–3）
```

这属于 **sequential exploratory mixed-methods design**，报告的 Methods 部分应点名这个术语——它把"我们做了两件事"升级为"我们设计了一条论证链"。

**分工原则**：interview 回答"**为什么 / 怎么发生的**"，questionnaire 回答"**有多普遍 / 排第几**"。同一 construct 两边都出现，但**形式必须不同**，否则只是重复，不是互证。

### 4.2 Semi-structured Interview Guide — 学生版（约 45 分钟）

**四条设计原则**（写进 Methods 是加分项）
1. **前 3/4 绝不提我们的方案**——一提就污染，后面所有回答都变成对我们的迎合
2. **使用 critical incident technique**——问"最近一次真实发生了什么"，不问"你一般会怎么做"（后者拿到的是自我形象，不是行为）
3. **隐喻测试放最后，且必须用实物**（mock ticker card），不能口头描述
4. **主动索取负面反馈**——明确问"哪里让你不信任"，否则只会得到礼貌

---

**Part 0 · 开场与知情同意（2 min）**
- 研究目的、录音授权、匿名化、随时可退出

**Part 1 · 背景（3 min）**
- 专业、年级、预计毕业时间
- 是否国际学生
- **是否有投资 / 股票经验** ← 后面分组分析要用（U2 的 equity 检验）

**Part 2 · 重现一次真实决策（10 min）— critical incident**
- 带我回到你最近一次要决定「学什么 / 选哪门课 / 投哪个方向」的时候，那是什么时候？发生了什么？
- 你当时查了哪些东西？**按顺序**说。
- 你跟谁聊过？为什么是这个人？
- 有没有你**想问但没问**的人？什么拦住了你？
- 最后是什么让你下定决心的？ ← 探测决定性因素是**数据**还是**人**

**Part 3 · 信息与信任（8 min）**
- 你刚说你看了 X，你多信它？为什么？
- 有没有哪次你查到的信息后来被证明是错的或过时的？
- 什么样的来源对你来说算可信？（probe：官方 / 学长 / 数字 / 招聘广告本身）
- **你觉得现在澳洲市场上什么技能最抢手？你怎么知道的？** ← 极有价值：测「确信程度」与「证据强度」的落差

**Part 4 · 人际获取（10 min）**
- 你约过学长或从业者聊天吗？说说那一次。（若没有：「什么阻止了你？」）
- 假如一个陌生从业者答应跟你聊 20 分钟，**你会问什么？** ← 直接产出 conversation starter 的设计输入
- 什么会让你觉得这次聊天有价值 / 纯属浪费时间？
- 聊完之后你做了什么？有记下来吗？ ← 检验 T5 的 L0/L1 层级
- 对方不回你或者拒绝你，你会怎么反应？

**Part 5 · 概念探测（12 min，拿出 mock）**
- 先给**不带隐喻**的 skill trend card：「你从这里读出什么？你会因此做什么？」
- 再给**带股票隐喻**的（持仓 / 涨跌 / watchlist）：同样两个问题
- 关键 probe：**「这里的 38% 是什么意思？」** ← 直接测误读
- 「如果它告诉你 Rust 在涨，你真的会去学吗？还需要什么你才会行动？」（RQ3）
- 「这两块——看数据、找人聊——对你来说是一件事还是两件事？」（RQ6）
- 「这个界面哪里让你不舒服或者不太信？」
- **额外 mock：一个技能很少的新生画像** ← 测 2d 中的伦理风险（"你的仓位很弱"是否打击人）

**Part 6 · 隐私与代价（5 min）**
- 为了拿到个性化建议，你愿意告诉它什么？什么绝对不给？
- 你的 watchlist 被从业者看到，OK 吗？

**Part 7 · 收尾（2 min）**
- 「我今天有没有漏问什么你觉得重要的？」
- 滚雪球招募

### 4.3 Semi-structured Interview Guide — 从业者版（约 20 分钟）

> 供给侧只能靠 interview，questionnaire 抓不到他们。这本身是一条 limitation。

- 被学生约过吗？体验如何？
- 什么情况下你会答应一个陌生学生？什么会让你**直接忽略**？
- 20 分钟 vs 45 分钟，哪个你更可能答应？
- 你希望学生提前给你什么？
- 一个月最多几次是你的上限？
- ⭐ **「因为你会 Rust、而这个技能正在涨、有个学生正在考虑要不要学它」——这个匹配理由让你更愿意还是更不愿意答应？** ← 直击 C7，整个产品论点的**供给侧检验**
- 如果只需要一次点击确认「聊了 / 没聊成」，你愿意吗？（验证 T5-L2）

### 4.4 Questionnaire 骨架

> 选项须在 pilot interview 之后生成，现列骨架。

- **S0 同意书 + 筛选**（是否 USYD 在读）
- **S1 人口学**：年级、学院/专业、是否国际学生、**是否有投资经验**（分组变量）
- **S2 现有行为**：过去 12 个月找过就业信息的场景（多选）+ 频率；使用过的信息来源（多选 checklist，选项来自 interview）+ 每项信任度 5 点量表
- **S3 决策单位**：强制排序题「你更想知道 A 哪些技能在涨 / B 哪些职位在涨 / C 哪些公司在招 / D ...」← 检验 U1
- **S4 Y 轴优先级**：从 §3.2 的清单中**强制排序前 5** ← 直接产出 Task 4c 的 must/should/nice
- **S5 咖啡聊**：过去 12 个月**实际约过几次**（行为题）+ 障碍 checklist + Likert
- **S6 隐喻理解测试**：放同一张 mock 图 + **3 个单选理解题（仅一个是正确解读）** + 「这张图让我更清楚 / 更困惑」量表 ← 检验 U2
- **S7 行动意图**：「看到这个之后我会 ___」多选 + Likert
- **S8 功能优先级**：8 张功能卡片做简化 card sort ← 检验 U8
- **S9 信息披露**：逐项 yes / no / 看情况（专业、GPA、签证状态、被拒经历、watchlist 公开）← 检验 U7
- **S10 招募**：「愿意参加后续 20 分钟访谈吗（留邮箱）」

### 4.5 交叉验证映射表

| Construct | Interview（深度） | Questionnaire（广度） | 交叉怎么用 |
|---|---|---|---|
| 现有信息来源 | 「上次你查了什么，按顺序」开放叙述 | 来源多选 checklist + 每项信任度量表 | interview **生成选项**，questionnaire **验证分布**。若「其他」被大量选中 → interview 覆盖不全 |
| **决策单位（U1）** | 「你当时到底在纠结什么？」 | S3 强制排序 | 两边一致 → 粒度定案；不一致 → 检查 interview 是否被引导 |
| 触发时机（U4） | critical incident 的具体时点与情境 | S2 场景多选 + 频率量表 | interview 给场景，questionnaire 给频率 → **决定 glance 还是 deep 做默认视图** |
| Y 轴优先级 | 「你最想知道什么？」开放 | S4 强制排序前 5 | **需求优先级不是我们拍的，是数据给的** → 直接进 Task 4c |
| 咖啡聊意愿与障碍（U5） | 叙述障碍与情绪 | S5：障碍 Likert **+ 行为题「实际约过几次」** | 妙处：questionnaire 拿**行为**，interview 拿**理由**。行为数据可检验自我报告有无夸大 |
| **隐喻可理解性（U2）** | 给 mock，让他讲出来错在哪 | S6：同一张图 + 3 个理解题 + 清楚/困惑量表 | 最漂亮的一组：interview 说明**错在哪**，questionnaire 给出**错误率**。再按「有无投资经验」分组 → **量化 equity 风险** |
| 行动意图（RQ3） | 「还需要什么你才会行动」 | S7 | 报告须主动承认 **intention ≠ behaviour** |
| 两功能是否一体（U8/RQ6） | 直接问感知 | S8 card sort：看「数据类」与「找人类」功能是否被排在一起 | 排序是行为化的，比直接问更抗迎合 |
| 信息披露意愿（U7） | 讨论边界与条件 | S9 逐项 yes/no/看情况 | 敏感项**匿名问卷更可靠 → 以 questionnaire 为主证据**，interview 只负责解释原因 |
| 伦理风险（"仓位很弱"） | 新生画像 mock 的反应 | 情绪量表：「看到这个我会感到 受挫 / 有方向 / 无感」 | interview 找机制，questionnaire 估比例 |

**方法学操作要点**
- 放 **1–2 道措辞完全相同**的题在两边做一致性检验（不一致本身就是可讨论的发现）
- questionnaire 结尾的邮箱招募，既是渠道，也在方法学上把两个方法 link 起来
- 建议在报告中写一句**预注册式声明**：
  > 「若 questionnaire 显示学生主要以 job title 而非 skill 为决策单位，我们将把 ticker 的粒度从 skill 改为 role，并把 skill 降为 role 的下层属性。」
  >
  > 明确写出「什么发现会改变什么设计」，远强于事后解释数据，直接呼应 U1。

### 4.6 抽样、伦理与协议要素（对应 Task 3b i–v）

| 项 | Questionnaire | Interview |
|---|---|---|
| **Who** | USYD 在读学生，N ≈ 40–60，**跨年级、跨学院**，demographic 中**必须分层出国际学生**（§2.4 论证过该群体被系统性亏待，不分层就浪费了这个论点） | 学生 5–6（覆盖大一/大三/毕业前）+ 从业者 2–3 |
| **Where** | 在线（Qualtrics / Google Forms），通过学院群、社团、课程公告分发 | 线上会议或校内安静场所 |
| **When / 多久** | 开放 7–10 天，单份 8–10 分钟 | 学生 45 min，从业者 20 min |
| **Instruments** | §4.4 骨架 + mock ticker card 图 | §4.2 / §4.3 guide + 两张 mock（含新生弱画像） |
| **Procedure** | 同意书 → 分发 → 提醒 → 关闭 → 清洗（剔除完成时间过短） | 同意与录音授权 → 按 guide 半结构化推进 → 转录 → thematic analysis（两人独立编码后比对） |

**必须写进 limitation 的短板**
1. **供给侧（从业者）只有 interview 数据、样本极小**——本次调查最大短板
2. 便利抽样，USYD 单校，无法推广
3. Intention ≠ behaviour
4. mock 引发的反应可能受呈现方式影响（single-exposure bias）
